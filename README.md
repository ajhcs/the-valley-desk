# The Valley Desk

Product source. Human news + agent feed. Delaware Valley / Greater Philadelphia healthcare technology.

Owner: Cole Lyons (co-founder). Engineering: Knox. Product: Reed. Brand: Mira. CEO: Vale.

Vite + React + TypeScript + TanStack Router + Tailwind on Cloudflare Workers. Humans get News, Events, Voices, a local-product watch, and an anti-FOMO event calendar. Agents GET `/feed.json` using the same `ContentItem` envelope. Signed editorial source: `fixtures/catalog.json`.

## Automation

One production Worker runs a 15-minute freshness lane and a daily catch-up lane. Every scheduled pass checks newsroom RSS, current chapter events, and configured social sources; the daily pass provides a second bounded reconciliation window. Both write every raw candidate to D1 before any model call. Muse Spark 1.2 Contributor (`meta/muse-spark-1.2-contributor`) classifies and grounds relevant candidates through OpenRouter's OpenAI-compatible API. Deterministic rules—not the model—make the final publication decision.

The same locked hourly run seeds the 16-system executive coverage registry and performs bounded checks against enabled first-party leadership sources. Every canonical system has an explicit active or degraded official-source posture; transitional, partial, and PDF evidence is retained as metadata without being used to infer departures. LinkedIn inventory is reusable for identity context but is never fetched. Complete, non-hostile snapshots produce protected observations. Additions and title changes are applied automatically only after two consecutive daily snapshots or two independent registered official sources; departures additionally require two consecutive complete snapshots from independent official sources. Conflicts and incomplete evidence remain unresolved. Verified changes emit review-status editorial candidates; they never publish directly. The observation endpoint is for diagnostics and explicit override only.

The automatic editor-in-chief publishes official future chapter events when their official source and attendance link validate without model calls. Other events and news go through deterministic specialist lanes for news, policy, finance, procurement, products, events, voices, and leadership. Each lane keeps its own quota and freshness ordering, while a hard per-run cap (default 32, concurrency 2, deadline 110 s per editorial pass) bounds runtime. Every nonempty lane receives capacity, unused quota is redistributed, and each pass reserves room for current news, time-sensitive events, and current executive/social evidence before lending capacity to the durable backlog. Fresh source publication dates outrank later article-hydration timestamps. Every run merges up to 1,000 durable D1 review candidates with the current snapshot and deduplicates by canonical source identity. News requires a named local health system, a material operating/technology change, literal evidence spans, and impact/body copy that is verbatim-supported by the source; cited context must likewise be verbatim-supported by verified prior coverage. First-party and exact-registry sources use a moderate evidence floor, while the Inquirer and WHYY may publish at a higher corroboration floor; unknown secondary sources still require first-party corroboration. Source-dated items older than 45 days cannot auto-publish, delayed runs preserve the source date instead of making backfill look current, and exact-registry discoveries without a verified source date remain in review. A structured claim-ledger maps atomic claims (names/numbers/dates/roles) to evidence spans/source/context IDs with exact-match enforcement, while source text remains untrusted. High-risk news classes (financial, policy/regulatory, security/safety/outage, executive change) pass through an independent second verification window that fails closed and never adds facts. Unsupported paraphrase, unverified claims, instruction-like source text, or model-written claims stay in review. Model transport/provider failures cool down with exponential backoff; evidence-validation rejections stay visible in metrics but do not generate outage mail, and an empty cooldown queue is not treated as provider recovery. Changed fingerprints become eligible immediately.

Allowlisted HTTPS article pages are fetched after RSS discovery. JSON-LD `articleBody` wins, then `article`/`main`. Normalized text is cached in D1 by URL (`0011`); successes refresh after 7 days, while `failed`/`no-content` cool down from 6 hours with exponential backoff capped at 7 days. A failed refresh keeps the last successful body so the full article never regresses to the RSS snippet. Raw HTML is never stored. The candidate cap is round-robin across sources; exact-host HTTPS, redirects, size, time, and concurrency bounds stay closed.

Every source check records a specific outcome—healthy, healthy-empty, disabled, misconfigured, auth-failed, rate-limited, upstream-failed, parser-failed, or timed-out—plus item count, last success, and consecutive failures. The hourly and daily lanes share a durable lock, source state, alert fingerprints, and recovery counters, so a retry or Worker isolate cannot duplicate notifications or erase an incident. An automatically published event is withdrawn only after two healthy, complete checks of its authoritative source omit it. Timeouts, HTTP failures, empty snapshots, parser-shape changes, catastrophic count drops, partial feeds, and rolling RSS windows never trigger disappearance withdrawal. Explicit cancellations stay on the permalink as cancelled and drop off upcoming; completed events keep their URLs. Missing social tokens and unsupported person accounts are recorded as misconfigured rather than empty success.

Untrusted email and LinkedIn notifications are pointers only. The hourly signal-verification stage (`0018`) checks at most 20 discoveries/40 URLs, strips tracking data, requires a normalized HTTPS host/path in the official source registry, re-checks the final redirect, and extracts a bounded candidate from the fetched first-party page. Instruction-like source text, unmatched hosts, unsupported pages, and transient failures remain explicitly rejected/failed with durable provenance and retry state. Verified candidates are deduplicated and sent through the normal raw-persist, Muse, editor, and second-pass gates; no signal can publish directly.

Vale’s social collector is a separate, review-only lane. `GET /api/signals/social/manifest` returns the hashed covered-account/current-executive target manifest; `POST /api/signals/social` accepts bounded LinkedIn/X evidence packets; and `POST /api/signals/social/runs` records a manifest-bound collector receipt. All three routes use `SOCIAL_INGEST_TOKEN`, which must be distinct from `REVIEW_API_TOKEN`, `OPENROUTER_API_KEY`, and platform credentials. LinkedIn targets remain inventory-only until `SOCIAL_LINKEDIN_ACCESS_VERIFIED=true` is explicitly provisioned after connector access is verified; X remains inactive until both access and verified targets exist. Social packets remain evidence until the ordinary Muse/editor publication gates succeed. Keep the external Vale routine paused until a production manifest fetch, packet ingest, scheduled consume/ack, idempotency replay, and `/ops` receipt have all passed.

Approved content is written to `published_content`. The Worker merges that D1 overlay into the bundled signed catalog for HTML, dynamic permalinks, `/feed.json`, `/api/content`, `/feed.xml`, and `/sitemap.xml`. If D1 is unavailable, the bundled catalog remains a complete fallback. Automated rows cannot replace editorial rows or set the featured lead.

Product news is admitted to model review only when `fixtures/product-watch.json` verifies that a named regional health system uses the mentioned product. Generic vendor marketing and unverified local-use claims stay out. The official-source discovery lane also watches three verified product/vendor channels (Epic and Microsoft) and three exact, institution-scoped procurement pages (Penn, CHOP, and Cooper). Product/vendor candidates carry a trusted mapped-product relationship; procurement candidates must additionally name a mapped product for the covered institution. Both categories require an accepted Muse regional/materiality result before entering the normal evidence editor and second-pass verifier, and remain review-only until those downstream gates pass.

Public URL generation uses `PUBLIC_ORIGIN=https://thevalleydesk.org`. The same Worker remains available on its workers.dev hostname for operational fallback; `www.thevalleydesk.org` redirects to the apex. See `docs/OPERATIONS.md`.

### Local verification

```bash
cp .dev.vars.example .dev.vars
npm test
npm run build
CI=true npm exec -- wrangler d1 migrations apply the-valley-desk --local
npm run ops:smoke
npm exec -- wrangler dev --local --test-scheduled
```

Trigger the local cron at `/cdn-cgi/handler/scheduled?format=json`. Public health is `GET /api/health` (`ok`, schema version, build SHA). Private endpoints are:

- `GET /api/automation/status`
- `GET /api/automation/status/review`
- `GET /api/review-queue?status=review`
- `POST /api/review-queue/:id/decision` with `{"decision":"approved","note":"..."}` or `{"decision":"rejected","note":"..."}`
- `GET /api/executive-observations?status=unverified`
- `POST /api/executive-observations/:id/decision` for diagnostics or an explicit `verified`/`ignored` override; routine verification is autonomous
- `GET /api/signals/social/manifest` with `Authorization: Bearer $SOCIAL_INGEST_TOKEN`
- `GET`/`POST /api/signals/social/runs` with the same token for the Vale collector receipt

Machine review/status routes require `Authorization: Bearer $REVIEW_API_TOKEN`; social routes require the separate `SOCIAL_INGEST_TOKEN`; `/ops` and `/ops/api/*` use Cloudflare Access context instead. A valid approval publishes immediately through the same dynamic content layer. `HEAD` is supported on public machine routes and private GET APIs. GitHub Actions runs locked install, tests, typecheck/build, local D1/scheduled smoke, `npm audit`, and a secret scan without production secrets.

### Cloudflare provisioning

1. Create the single D1 database: `wrangler d1 create the-valley-desk`.
2. If Wrangler does not provision the binding automatically, add the returned `database_id` to the root D1 entry in `wrangler.jsonc`.
3. Apply migrations remotely: `wrangler d1 migrations apply the-valley-desk --remote`.
4. Add secrets with `wrangler secret put REVIEW_API_TOKEN`, `wrangler secret put SOCIAL_INGEST_TOKEN`, and `wrangler secret put OPENROUTER_API_KEY`. These are separate credentials: `REVIEW_API_TOKEN` authorizes machine review operations, `SOCIAL_INGEST_TOKEN` authorizes only Vale manifest/evidence/receipt routes, and `OPENROUTER_API_KEY` authorizes model spending. Neither token belongs in Git, browser code, or `wrangler.jsonc`; provision the same social token only in the one approved Vale routine.
5. `EDITOR_MODEL` is pinned to `meta/muse-spark-1.2-contributor`; `EDITOR_MODEL_BASE_URL` defaults to `https://openrouter.ai/api/v1`. There is no automatic fallback to standard Muse. Contributor requires OpenRouter Settings → Privacy to allow routing to providers that may train on prompts; any account or guardrail Zero Data Retention enforcement for non-frontier models must also be disabled for this key. If those policies block the endpoint, OpenRouter returns HTTP 404 and the item cools down in review while deterministic official-event publication continues. Muse is a reasoning model: calls request low reasoning effort, keep a 4,096-token shared reasoning/output budget, request `json_object`, and extract JSON from fences/whitespace without loosening Zod or evidence checks. Each scheduled invocation selects at most `EDITOR_MODEL_BUDGET` (default 32) eligible items across specialist lanes with `EDITOR_MODEL_CONCURRENCY` (default 4). Calls time out after `EDITOR_MODEL_TIMEOUT_MS` (default 45s); enrichment and high-risk verification each receive a bounded `EDITOR_MODEL_DEADLINE_MS` window (default 110s) inside the scheduled handler's `waitUntil` work. Set `EDITOR_MODEL_BUDGET=0` to disable model calls without stopping official-event publication.
6. Keep the machine review/status routes undiscoverable and bearer-token protected. Configure Cloudflare Access for `thevalleydesk.org/ops*` with only `clyons@ajhcs.org`; the Worker also requires `ctx.access`, so direct `workers.dev/ops` requests remain denied. The browser operations surface uses `/ops/api/*` and never receives `REVIEW_API_TOKEN`.
7. Run `npm run deploy` to update the one existing `the-valley-desk` Worker with the current git SHA as `BUILD_SHA`. The configured apex and `www` Custom Domains are attached to that same Worker; no second Worker is created.
8. Operations, rollback, D1 Time Travel, alert thresholds, and the Cloudflare Bot skip-rule requirement are in `docs/OPERATIONS.md`.
