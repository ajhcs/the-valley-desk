# Dataset directory operations

Migration 0050 creates `dataset_visibility` with the switch off. Load reviewed dataset JSONL with `ops/load-research.py --datasets PATH`; use `--respect-removals` for imports. Dataset IDs in `dataset_removals` hide records immediately. Add removal IDs using `--dataset-removals PATH` (a JSON array), and refresh summaries after removals.

Run `ops/research-summary.sql` after every import, removal, or visibility change. It refreshes counts, partner counts, and dataset filter choices. Switching off hides dataset records immediately; refreshed summaries are required for current counts and choices when switching on. The visibility change and summary refresh are separate operational actions; neither is performed by this documentation.

Migration 0051 stores reviewed paper-to-data reuse edges separately from dataset listings. `python3 ops/load-research.py --reuse-edges PATH` accepts JSONL with exactly `paper_id`, `dataset_id`, `evidence_url`, `evidence_quote`, `reviewed`, and `public_safe`. Both review fields must be true; the evidence must establish that the paper reused the identified repository record and the metadata must be reviewed for public safety. Preserve this projection and supporting evidence privately. Automated inference decisions are not this projection and do not approve publication. The loader recognizes only the canonical repository identities implemented in `reuse_accession`; unsupported identities require a separately reviewed extension. It validates the whole input before emitting edge statements. Existing edges are upserted, not pruned; removal requires a separately reviewed SQL change or the existing paper/dataset removal controls.

The publication page reads reuse edges only while `dataset_visibility` is enabled and hides an edge immediately if its dataset ID is in `dataset_removals`. Publication visibility and removals continue to govern the page. Repository links are derived from accession identities rather than supplied URLs; these edges neither create directory listings nor establish a regional connection. The migration's revision triggers invalidate cached directory responses when edges change. Apply 0051 and load reviewed edges only under a separate authorized release; do not include them in the 0050 rollout.
