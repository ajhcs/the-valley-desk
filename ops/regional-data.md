# Regional data freshness and publication links

The daily directory runner leaves this feature off unless its private state directory contains `regional-data-config.json` with `{"enabled":true}`. Install no new service or timer. After the regional-data migration, source review, initial load and separate operational authorization, place that private file in the existing daily service's state directory; the existing timer will use it on the next run. Remove the file or set `enabled` to false to disable it. Do not enable it merely by merging these files. Missing schema or configuration is safe.

The checker reads loaded regional listings directly, including hidden listings, and excludes removed IDs. It visits only CDC JSON metadata endpoints and pointers recorded in `scripts/regional-data/evidence.json`; unrecognized or missing locators enter review without a request. Requests run sequentially, have a 20-second timeout, a 2 MB response bound, at most three attempts and exponential backoff. Redirects are rejected. Each listing is attempted at most once per day. Successful checks record the publisher date and check date privately; failed checks retain the last successful values and record a review reason. A publisher date over two years old is flagged for review, not proof that the dataset is obsolete. Missing or invalid dates and future dates are failures. No contact details or source response bodies are retained by this checker. The staged SQL shares the daily lock, hash, revision guard and retry path; it never modifies or removes canonical listings. A plan stages a private run artifact and does not write to D1.

`ops/regional-data-publications.json` is an intentionally empty template, not an automated matching rule. A link needs human review of the actual paper: the paper must explicitly name the exact dataset/release and describe its use. Keep the source URL and supporting passage in a private reviewed JSON array, with fields `dataset_id`, `paper_id`, `source`, `evidence`, and `reviewed: true`. Obtain current loaded listing inventories as private JSON arrays of objects with `id`; then stage locally:

```
python3 ops/regional_data_freshness.py --reviewed PRIVATE-REVIEW.json --datasets PRIVATE-REGIONAL.json --papers PRIVATE-PAPERS.json > PRIVATE-LINKS.sql
```

Review the resulting SQL and apply only through a separately authorized load. IDs must exist in the supplied inventories. This tool cannot verify the source passage or the inventories' freshness; the reviewer must do so. Link display separately requires both records to be visible. Never infer a link from a similar title, a related portal, geography, or publication date. A repository search found a potential county-stroke paper (doi:10.1002/ana.27039) but it predates the 2025 PLACES seed release, so no link is staged. Other candidates require full-text review.
