The candidate remains disabled. No migration, deployment, source fetch, flag change or production deletion has been performed. This note proposes the exact scope for a user decision; accepting the code candidate does not itself enable it.

The same capture-window cutoff is enforced by both application code and the SQLite/D1 trigger. Receipt, insertion and expiry timestamps are distinct. The trigger is tested with an injected database clock and the real SQLite clock; that is offline compatibility evidence, not proof of live D1 execution. Production application of the exact migration and smoke verification remain separately authorized release actions.

Deletion here means deletion from the live capture table and authorized export files. Cloudflare D1 history can restore pre-deletion data within its existing Time Travel period (documented as up to 7 days on Free / 30 days on Paid); this patch does not change or erase that provider history. The actual account plan was not queried or changed. [Cloudflare Time Travel documentation](https://developers.cloudflare.com/d1/reference/time-travel/) supports this limitation. Therefore this proposal is **not** a guarantee that every historical backup copy disappears on Oct 6. If that stronger retention requirement is needed, do not enable this D1 capture proposal as written.
