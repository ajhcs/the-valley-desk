# Operating inputs and decision risks

This register identifies information and resources that implementation must
establish. It does not claim that access, staffing, funding or operational
authority already exists. Resolve available repository/tool/session evidence
before asking the user; continue independent work while a specific input is open.

Existing authorization persists when the later implementation task supplies it;
do not repeatedly ask for the same permission. Conversely, an engineering
document, an agent's recommendation or a previous unrelated production success
does not supply missing source access or release authority.

## Risks and reconsideration triggers

These are qualitative failure modes with observable controls, not numerical
probability estimates or an executed fault-tree analysis.

| Risk | Earliest discriminating check | Owner and response | Acceptance effect |
| --- | --- | --- | --- |
| Same-name merges or misdated affiliation create false local creators | WP03 identity challenge set and WP14 claim-specific adjudication | WP04/WP14: hold unsupported joins, correct/split accepted errors, invalidate dependents | Any observed critical error blocks E01 acceptance until repaired/retested. |
| Model/source text or forged reviewer field bypasses publication authority | WP14 unauthorized request tests and WP22 hostile-input cases | Reject at authenticated mutation boundary; preserve incident evidence and inspect affected public records | Publication bypass/private leakage blocks release. |
| Boolean model guard fails to correspond to actual multi-row transaction or stale writer | WP16 real D1 fault/interleaving tests | Use immutable versions, complete dependency vector and a guard that actually aborts | P11/P28 correspondence remains unqualified until demonstrated. |
| Stable pagination serves revoked claims or silently loses members | WP17 correction/expiry between pages | Explicit snapshot invalidation/restart; measure restart frequency and usable lifetime | Invalid content or false partition blocks acceptance; unusable restarts require design revision. |
| Restored data resurrects old cursor or withdrawn claim | WP26 old-snapshot restore with matching old heads/epoch | External recovery incarnation plus reconciliation of post-backup corrections; keep public discovery closed when unresolved | Failed non-resurrection check blocks recovery and release readiness. |
| Required provider cannot be accessed or has incomplete identities/affiliations | Small permitted route qualification before broad enrollment | WP06/provider owner: document gap, obtain permitted alternative within route or propose explicit scope change | Fixture success cannot complete the six-route gate. |
| Review backlog, provider cost or correction load exceeds available capacity | WP25 predeclared four-week pilot and incident/cap counters | Terra/operator: pause affected intake, adjust staffing/extraction/enrollment transparently | A completed negative study is not `release_ready`. |
| Reference set leaks duplicate projects or overrepresents known institutions | WP03 family-group split review and external reference research | Preserve grouping, route/type/county strata and untouched evaluation; audit outside-reference discoveries | Invalid or consumed holdout cannot support an accuracy/recall claim. |
| Search is formally ordered but unhelpful | WP20 development tasks and WP24 held-out reader evaluation | Compare observed error classes against the deterministic baseline, revise ranking with new tests/evaluation | Correct comparator alone cannot satisfy E05. |
| Legacy URLs or feeds break while editorial focus changes | WP19 consumer matrix and WP26 upgrade/rollback tests | Preserve legacy meanings and stable access; separate reduced new-content effort from service deletion | Broken required consumers block transition. |
| Source permissions change after evidence was retained | WP05/WP06 rights-revision test | Stop new fetch/display as required; remove/redact when retention no longer permitted, keep only permitted audit material | Dependent claims must be held/invalidated when evidence can no longer support publication. |

Review this register at each gate and when new evidence changes a design
assumption. Record an owner, observed finding, action and recheck. Do not close a
risk merely because its work-package document has been written.
