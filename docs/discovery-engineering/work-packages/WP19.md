# WP19: Worker routing, crawlers, metadata and legacy compatibility

**Owner:** Terra  |  **Reviewer:** Sol  |  **Phase:** I06  |  **Dependencies:** WP17, WP18  |  **Status:** not_started

## Purpose and contract

Deliver R11–R12 and R15–R17 across direct Worker requests, React navigation and crawler output, consistent with C_LEGACY, C_DELIVERY and P14, P20, P28. Existing [Worker routing](../../../worker.js) explicitly returns 404 for `/org` and its descendants; [router](../../../src/router.tsx) comments that org-ID routes are not minted. The new `/organizations` route deliberately supersedes the no-organization-page product decision, while `/org` remains 404 unless a separately reviewed identity-preserving migration specifies otherwise. Update the obsolete comment in the implementation rather than pretending the old route exists.

Define a single route and status matrix for Explore, Work, People, Organizations, optional projects, their details, not found, unavailable and private review. Ensure direct navigation, client navigation, refresh and crawler requests return consistent public content, canonical identity, HTTP status and metadata. Crawler HTML must use the same admitted public projection as React, never candidates or private evidence. Generate meaningful titles, descriptions, canonical links and structured data only when supported; escape source text and constrain URL schemes. Verify robots and sitemap include only eligible public URLs, including removal or correction after invalidation.

Preserve existing news, events, technology and policy Watch pages, APIs, feeds and calendar consumers. Do not redirect unless the replacement preserves verified identity and semantics. Document path ownership and old consumer examples. Snapshot continuation binds actual normalized query, sort and immutable version; material projection changes invalidate via epoch and yield 410 with the query retained. Initially route discovery through primary reads and no-store headers; test public and crawler behavior at this boundary.

Prepare a compatibility matrix and future synthetic Worker integration tests. Coordinate schema/API contracts with WP17 and the UI with WP18; WP26 handles recovery rehearsal.
