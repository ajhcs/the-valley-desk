## Implementation and interface contract

1. Compile separate public work, creator, organization and project payloads from admitted fields only. Build strict allowlists for summaries, evidence links, dates/stages, professional roles, regional basis, supported relations and rights. Exclude raw candidates, contact emails, private notes, credentials and rejected claims. Unknown license cannot become unrestricted reuse.

2. Produce an immutable manifest with subject/input revision, payload/schema digest, accepted decision revisions and the complete dependency vector: evidence/claim heads, identity/alias decisions, relation and endpoint admission heads, dated affiliation/county claims, source configuration/permission/expiry, geography/relevance/review policies, verification rules and artifact-license heads. Enumerate dependencies transitively and reject missing required kinds.

3. Publish in one transaction: assert expected heads and current validity, append decision/manifest/public revision, advance subject head and generation, and update invalidation state. A conditional UPDATE matching zero rows does not abort a batch. Use an unconditional guard-row insert with CHECK(ok=1), or an equivalent aborting trigger, that fails if ANY expected row/revision/digest is missing or changed. Assert prior public revision similarly; do not rely on application pre-reads.

4. Increment generation for additions. For withdrawals, corrections, changed admission/identity/rights/policy dependencies or expired validity, invalidate current delivery and affected snapshots in the same transactional state transition; initially a conservative global invalidation epoch is acceptable. Keep immutable historical evidence/revisions. Do not reuse a stale admitted payload under a new manifest.

5. Default public reads to primary-consistent database access and no-store HTTP/CDN responses. Recheck dependencies and validity at detail/query reads using one delivery instant. Snapshot reads also validate epoch and earliest dependency expiry. A snapshot may survive additive records, but cannot serve stale material claims. WP17 owns continuation errors and immutable membership.

## Acceptance criteria

- **AC-WP16-01:** Race two publications with the same expected public revision; exactly one commits and the loser leaves no manifest/generation side effects; retain database readback.

- **AC-WP16-02:** Mutate each dependency kind independently after compile; publication aborts wholly, including zero-row/missing-head cases; retain mutation matrix.

- **AC-WP16-03:** Publish an account/relationship with unadmitted endpoint or spoofed model acceptance; no public revision appears; retain negative fixtures.

- **AC-WP16-04:** Revoke permission, correct affiliation or expire a claim; current detail disappears/updates and old snapshots require restart atomically; retain read/race trace.

- **AC-WP16-05:** Add an unrelated admitted item; generation advances while an otherwise valid old snapshot keeps its membership; retain before/after traversal.

- **AC-WP16-06:** Insert private sentinel fields; payload, API/crawler output and cache responses expose none; retain allowlist/response assertions.
