## Implementation and interface contract

1. Preserve the bounded existing path as a compatibility reference: Plan accepts only inst-regional-wistar, five items, offsets through 100 and a window up to 90 days; qualification binds Wistar/Philadelphia evidence. Its manual two-request transport does not activate production collection. Replace neither these limits nor that trust boundary implicitly.

2. Add discovery-owned qualified institutional scopes with versioned affiliation search literals and nine-county evidence. Search terms identify candidates; per-author metadata and admitted institution/location evidence establish historical regional attribution. PubMed metadata alone cannot assert current employment or unique person identity.

3. Bind search result IDs, query/window, offset and fetch response to the collection receipt. Use PMID as provider identity; retain DOI as a supported cross-provider link proposal. Missing requested PMIDs, repeated IDs, mixed affiliations and partial author coverage remain explicit. A valid publication is representable with no repository or project.

4. Reuse safe XML structure/namespace handling, reject entities and unqualified vocabularies, and retain exact permitted metadata evidence. Keep contact emails out of public candidates. Preserve reported publication dates and partial precision through WP04; the current full-day helper cannot represent month/year dates and must not invent days.

5. Account independently for search and metadata-fetch requests under WP06 budgets. Enroll generated query/page URLs through reviewed templates rather than broad host access. Test corrections/retractions and changed metadata as new revisions; distinguish publication stage/status from discovery/ingestion time. Freeze corpus evaluation by institution/source group before tuning.

- **AC-WP09-06:** Interrupt after search or exhaust metadata budget; record incomplete coverage and resume safely without counting a healthy empty inventory; retain checkpoint trace.
