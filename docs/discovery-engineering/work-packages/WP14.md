## Implementation and interface contract

1. Implement separate creator and work gates. Creator admission needs identity, professional health-tech basis and dated regional evidence with no artifact prerequisite. Work admission needs healthcare purpose, substantive technical contribution and a regional creator role; incidental computers, generic AI, local adoption and geography alone fail. Admit account links, grouping and reuse claims separately.

2. Define review resources under the authenticated Ops discovery namespace: GET candidates/detail; POST proposals; POST candidate decisions. Decision input contains candidate revision/digest, action, claim IDs, evidence vector, policy versions, expected head and idempotency key. Return 201 for a new decision, 200 for an identical replay, 409 for stale/conflicting revision, 400/413/415 for invalid bodies and 503 for unavailable storage.

3. Authenticate before route dispatch using verified issuer/audience/signature and same-origin mutation controls. Derive authority server-side. Authenticated model/service proposals may stage suggestions but can never accept, publish or impersonate human reviewers. Deterministic-rule decisions require a registered qualified rule/version and server reconstruction from exact retained evidence; caller-supplied rule flags are insufficient.

4. Append immutable decision, rationale, unresolved fields, reviewer/rule identity and complete dependency references. Evidence/policy/permission changes between review and commit cause transactional conflict. The review endpoint creates admission, not a public projection; WP16 consumes accepted decisions through its own guarded publication path.

5. Develop and repair attribution/relevance rules only with the development corpus, retaining errors/disagreements by source group. Run held-out evaluation separately; any held-out case used to guide a repair is consumed and requires a newly frozen untouched evaluation set before a fresh accuracy claim. Preserve historical/current affiliation, source stage/status and supported endpoint distinctions. Public/private review response schemas must be separate explicit allowlists.

## Acceptance criteria

- **AC-WP14-01:** Submit a valid independent creator and a paper-only work; each passes its own gate without repository dependency; retain decision/evidence trace.

- **AC-WP14-02:** Submit generic AI, routine clinical content, unknown county and local adoption alone; corresponding claims remain rejected/unresolved; retain frozen-corpus outputs.

- **AC-WP14-03:** Use a valid authenticated model identity to request acceptance/publication; no decision authority or public row is created; retain authorization test.

- **AC-WP14-04:** Change evidence, permission or policy head during review; 409 occurs and no partial accepted decision commits; retain race/row readback.

- **AC-WP14-05:** Replay the same decision key then change its payload; identical replay is stable and changed replay conflicts; retain responses/history.

- **AC-WP14-06:** Call via alternate origin, invalid JWT, oversized body or spoofed reviewer/rule; deny safely without leaking private inputs; retain response allowlist tests.
