## Implementation and interface contract

1. Implement plan/parse/nextPage against the WP06 contract for reviewed organization/account inventories and bounded search leads. Existing parser covers metadata for an already enrolled repository plus its lists; it is not an independent regional discovery search. Add the missing route explicitly and preserve search scope, query, window and caps.

2. Use native numeric repository/account IDs as identity, retaining owner/name as versioned aliases. Reject unsafe numeric coercion and contradictory native bindings. A transfer/rename updates a supported alias without creating another repository. Repository owner, contributor and personal author are distinct roles requiring separate attribution evidence.

3. Retain repository baseline and release/tag/commit observations separately. Bind list parsing to a durable repository identity receipt. Do not infer release publication from tag or commit date, current maintenance from recent ingestion, regional creation from repository hosting, or unrestricted reuse from visibility.

4. Collect declared public profile links as identity leads, not accepted person merges or current affiliation. Preserve license metadata as a hint with a source/version reference; WP14 decides eligible public claims and WP16 projects admitted values. Source text remains untrusted, including README instructions and release descriptions.

5. Use bounded pagination validated by enrollment templates, conditional response validation against a retained same-endpoint representation, and typed rate-limit/auth failures. Access restrictions or search truncation produce explicit coverage gaps. Ensure creator-first and artifact-first plans can each start without another acquisition channel.
