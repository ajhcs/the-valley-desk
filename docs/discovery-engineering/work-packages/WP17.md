## Implementation and interface contract

1. Propose GET/HEAD /api/v3/discovery/{works,people,organizations,projects} and /{kind}/{id}; retain legacy APIs. Parse only bounded known keys, reject duplicate scalar keys/unknown facets and canonicalize set-valued facets. Initial limits: q≤200 characters, ≤12 distinct normalized terms, ≤20 selected values/facet, default page size 25 and maximum 100, cursor≤2048 bytes and total query≤16384 bytes; expiry≤15 minutes and earliest relevant dependency expiry. Freeze these in WP02.

2. Baseline exact text matching: NFKC, locale-independent lowercase, Unicode letter/number tokenization, deduplicate/sort terms; index admitted title/name, purpose and supported topic labels using the same versioned transform. Nonempty text requires at least one exact token match; score counts unique matching query terms. No stemming, inferred synonyms or opaque FTS relevance may change this baseline. Govern any explicit alias table as a versioned admitted policy dependency.

3. OR within each selected facet and AND across text/facet/date constraints. Support topics, creator/organization IDs, artifact kinds, exact county keys and separate current-local/local-at-creation modes. Missing facts fail positive filters. Source date intervals must fit wholly within [from,until); retain precision. Rank relevance by descending unique-term count, known-date first, descending supported interval lower bound, then ascending binary stable ID; recent omits term count. People/organization empty queries sort by normalized display name then binary stable ID; nonempty creator queries prepend unique-term match count to that name order.

4. Use the selected generation-view membership design: immutable public revision payloads and revision-bound tokens/facets, plus versioned visibility intervals, reconstruct exactly the rows valid at the pinned generation/asOf. Atomically create a finite snapshot descriptor with actual canonical query JSON, sort, schema/token/policy versions, generation, asOf, invalidation epoch, external recovery incarnation, expiry and page contract. Store the query itself, not only its digest; retain necessary old revisions/index entries until valid snapshots expire. A materialized membership-list alternative requires an adjudicated design change, not owner discretion.

5. Use a server-opaque unguessable cursor whose server-side receipt binds snapshot, complete last sort tuple, canonical query, sort, page contract and expiry; do not accept caller-edited positions. Read metadata/membership/epoch consistently; return the next positive-sized disjoint page and stable total/facets from that snapshot. Additions may preserve existing snapshots; correction/withdrawal/policy change, elapsed validity, missing membership revision or expiry returns 410 with code discovery-snapshot-invalidated or discovery-snapshot-expired as applicable. Recovery-incarnation mismatch invalidates every pre-restore cursor even if restored database heads/epoch match; unavailable external incarnation closes discovery reads. Query/sort mismatch returns 400; malformed/tampered cursor returns 400; unavailable storage returns 503. Never silently restart or silently skip invalidated members.

6. Default reads to primary access and Cache-Control/CDN-Cache-Control: no-store, with one delivery instant. Bound snapshot creation/storage and rate limits; oversized result cohorts return an explicit narrow-query outcome instead of a truncated complete claim. Facet counts describe admitted snapshot membership, never a global regional population. Measure restart frequency, usable snapshot-lifetime distribution and completed traversals under representative correction/expiry cadence; WP20/WP24 judge reader impact without inventing a performance threshold.

## Acceptance criteria

- **AC-WP17-01:** Compare exact query results/facet counts against an independent frozen oracle across duplicate terms, OR/AND and unknown facts; retain expected/actual sets.

- **AC-WP17-02:** Use partial dates, identical scores and non-ASCII IDs; order matches declared date/binary keys and ingestion changes none; retain comparator cases.

- **AC-WP17-03:** Traverse every page including size one; concatenation equals immutable ordered membership with no duplicates/omissions; retain revision IDs and page trace.

- **AC-WP17-04:** Add records during traversal; old membership/order remains unchanged while a new search sees additions; retain concurrent snapshot comparison.

- **AC-WP17-05:** Correct/withdraw a member, change policy or cross earliest validity/expiry; next continuation returns the applicable stable invalidated/expired 410 code without leaking stale rows; retain race tests.

- **AC-WP17-06:** Tamper cursor/query/sort or delete a required revision; reject explicitly and never fall back to current rows; retain status/payload assertions.

- **AC-WP17-07:** Execute work and people searches with private sentinel candidates; only allowed admitted projection fields appear, with no-store headers; retain endpoint tests.

- **AC-WP17-08:** Replay representative correction/expiry traffic and a restore with matching old database epoch but rotated external incarnation; measure restart frequency/lifetime and traversal outcomes, and reject all pre-restore cursors with 410; retain workload/reader-impact and recovery traces.
