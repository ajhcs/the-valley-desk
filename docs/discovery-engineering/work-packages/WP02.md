## Contracts and steps

1. Replace the native `ReviewDecision.candidate : Work` limitation with a typed review target covering creators, work, claims and relationships. Define target revision, authenticated authority, decision reason, policy revision, immutable evidence references and supersession. Extend native review/publish signatures for creators. A creator can qualify without indexed artifacts; names and model suggestions cannot authorize identity joins.

2. Generalize `LicenseAssessment.repository : Repository` to an artifact/version/scope target. Separate code, text, data and model-weight rights; preserve unknown and restricted states. Metadata access never supplies blanket reuse permission.

3. Replace mutable work references in `SearchSnapshot.results` with immutable public row revisions for both work and creators, plus actual normalized query, sort mode, generation, eligibility-as-of time, invalidation epoch, external recovery incarnation, expiry and a complete dependency vector. Enumerate evidence observations, accepted claims/decisions, endpoint and relationship revisions, identity resolutions, rights assessments, source enrollment/configuration, source qualification and permission activation/revocation revisions, verification-rule revisions, geographic/relevance/review/public-field policy revisions, currentness expiry and projection generation. Every materially used dependency must be represented.

4. Specify atomic compare-and-swap across that full vector and public row write. Use immutable revisions or monotonically increasing generations to prevent A→B→A/ABA reuse. Evidence/policy hashes alone are insufficient; a failed conditional write must abort the whole transaction, not leave later statements running. Read through a coherent primary database snapshot; serve `Cache-Control: no-store` initially. A stale replica or application cache cannot bypass invalidation.

5. Bind cursors to snapshot ID, complete normalized query, sort mode and position; reject malformed or mismatched tokens with HTTP 400. P20/P21 partition guarantees apply only while the snapshot remains valid. A material dependency or policy change, or expiry, invalidates the snapshot: return HTTP 410 with an explicit restart instruction. Do not silently remove rows or splice new content into remaining pages.

6. Freeze exact nine-county DVRPC keys, temporal intervals, current presence versus creation-time regional attribution, independent provider/native keys, provenance-origin equivalence, request/result envelopes and typed failure outcomes. Shared serialization must support all six routes without repository prerequisites.

## Acceptance criteria

1. **AC-WP02-01:** Given a creator without work and an evidence-backed relationship, the proposed decision schema represents independent review; evidence is reviewed native/type examples and a gap-resolution diff.

2. **AC-WP02-02:** Given paper, forum, code, data and weight rights, each receives versioned scope-specific assessment with unknown preserved; evidence is a contract case matrix.

3. **AC-WP02-03:** Given any dependency change between prepare and commit, the publication contract rejects stale writes, including ABA, source reconfiguration, qualification/permission revocation and verification-rule replacement; evidence is transaction pseudocode and enumerated race cases. A restore-incarnation change rejects all pre-restore continuations even when restored internal heads match.

4. **AC-WP02-04:** Given a valid multipage snapshot followed by policy change or expiry, continuation returns 410 and restarts without mixed revisions; evidence is a sequence specification covering primary reads and headers.

5. **AC-WP02-05:** Given GitHub, PubMed, Crossref, arXiv, forum and institutional inputs, interfaces admit independent creator/artifact paths; evidence is one reviewed fixture contract per route.
