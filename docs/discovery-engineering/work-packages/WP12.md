## Implementation and interface contract

1. Qualify installation-specific public API/RSS/HTML transport and topic/category/query scopes. Define native installation, topic, post, revision and account IDs; equal numeric IDs across installations are distinct. Choose one supported parser per enrolled installation/version instead of claiming a universal forum parser.

2. Implement independent topic/post discovery and preserve topic-to-post, reply and author-account relationships with exact source evidence. A relevant discussion can stand alone. Source text suggesting code or papers creates leads, not required dependencies, and never grants permission to follow new sources.

3. Keep forum accounts distinct from natural people. A biography, signature, linked institutional profile or explicit professional claim can propose an identity/affiliation link, but names and avatars cannot establish it. Date regional claims and distinguish contribution roles from mere membership or local adoption.

4. Retain only permitted public metadata/excerpts with source revision timestamps and edit/deletion markers. Exclude private categories, messages, emails and hidden profile fields. Treat medical anecdotes and user-supplied instructions as untrusted material; no instruction embedded in a post changes credentials, fetch scope or publication authority.

5. Implement bounded pagination and installation-specific backoff using WP06. A deleted/private post or revoked permission invalidates affected current claims without silently erasing the audit trail; actual restricted-content retention must follow the approved rights policy. Publish discussion stage/type honestly and avoid presenting forum assertions as verified clinical/scientific findings.

## Acceptance criteria

- **AC-WP12-01:** Discover one qualifying discussion with no repository/paper; it remains eligible for evidence review and a standalone reader path; retain fixture trace.

- **AC-WP12-02:** Use the same post/account IDs on two installations; stable keys remain distinct; retain identity readback.

- **AC-WP12-03:** Match an account display name to a known researcher; no person merge/current-local claim occurs without admitted link evidence; retain unresolved candidate.

- **AC-WP12-04:** Encounter a private category, message or hidden contact field; no unauthorized fetch/public projection occurs; retain mock requests and redacted payload.

- **AC-WP12-05:** Inject instructions into a post and an off-scope next-page link; neither changes transport scope or decision authority; retain adversarial results.

- **AC-WP12-06:** Edit/delete an admitted post or revoke rights; current claims invalidate while approved historical receipts remain auditable; retain revision and visibility trace.
