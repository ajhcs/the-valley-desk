## Implementation and interface contract

1. Persist collection run, frozen eligible cohort, ordered source IDs, round cursor, leases and budget reservations. Existing Watch scheduling orders due rows by next_due_at/source_id; that is not proof of the modeled round-robin contract. Implement a discovery-owned round whose membership stays fixed until completion, with explicit new-source enrollment in the next round.

2. Advance the cursor after each completed attempt, including blocked, failed and timed-out outcomes. Revoked sources record a skipped slot without being fetched. A changing external source cannot hold the round open forever. State conditional fairness precisely: continued dispatch and a finite fixed cohort guarantee slots, not successful upstream delivery.

3. Persist raw representation, normalized observations and a page receipt atomically under lease/configuration/permission guards. Include empty pages in durable acknowledgments. Advance only a contiguous, validated page chain; a missing terminal page, duplicate token, rejected row, truncation or write failure cannot produce completed inventory coverage.

4. On crash, resume from the last committed continuation with the same query/window/configuration binding, or start a clearly new cohort if upstream tokens have expired. Retried pages use stable idempotency identities. Separate last attempted, last successful, last complete and last public refresh instants.

5. Guard lease owner and expiry at every mutation; the old owner cannot write after takeover. Budget reservations and retained-byte accounting survive interruption; conservatively count uncertain requests. Expose stop/disable/backoff without deleting evidence. Use isolated clocks and fetch doubles in tests; production scheduling remains a later operational decision.

## Acceptance criteria

- **AC-WP07-01:** Crash after raw/page commit but before checkpoint acknowledgment; replay creates no duplicate identities and safely resumes; retain restart trace.

- **AC-WP07-02:** Fail the first source in a three-source round repeatedly; the other two still receive a slot in that round; retain ordered dispatch ledger.

- **AC-WP07-03:** Lose a lease between parsing and write; the stale owner commits no observations, checkpoint or health success; retain competing-worker results.

- **AC-WP07-04:** Provide an empty nonterminal page, a missing terminal page and a looping token; none claims complete coverage; retain page-chain fixtures.

- **AC-WP07-05:** Race request reservations and restart after uncertain dispatch; cumulative requests and retained bytes never exceed declared caps; retain budget readback.

- **AC-WP07-06:** Disable enrollment during a run; no further unauthorized fetch/write occurs, last-good evidence remains and coverage records the gap; retain permission-change trace.
