## Qualification contract and steps

1. Inventory public read, suggestion/correction intake, authenticated review, source enrollment, scheduler and publication boundaries. Record which identity authorizes each operation, required scopes, allowed origin and audit event. Preserve signature-verified issuer/audience checks and existing private-route behavior; a forwarded email header, model output or context object cannot authorize a decision.

2. Exercise missing, forged, expired and wrong-audience credentials; cross-origin mutation; direct alternate Worker host; oversized inputs; duplicate decision replay; unauthorized source enrollment; and identifier substitution across targets. Record failure status, unchanged durable state and sanitized audit events. Require one consistent contract for all mutating methods, including future PATCH/DELETE routes.

3. Treat source HTML, XML, markdown, titles and external links as hostile data. Test executable markup, dangerous URL schemes, prompt injection, parser expansion, redirect loops, MIME mismatch, decompression bombs and oversized responses. Model suggestions cannot bypass deterministic admission or trigger outbound calls.

4. Test transport destination policy before initial request and every redirect, including private/loopback/link-local addresses, DNS changes and credential forwarding to a new host. Bound request count, bytes, wall time, retries and concurrency; retain typed denial/failure rather than recording an empty successful source.

5. Attempt direct access to candidate evidence, reviewer notes, credentials, private contact details and hidden identity joins through APIs, HTML, crawler output, logs, errors and caches. Use field allowlists and documented public professional-contact policy. Corrections must not expose submitter identities or create an unreviewed publication route.

6. Specify retention per data class, immutable evidence retention exceptions, deletion/correction propagation, incident ownership and recovery. Race stale decisions and policy changes against publication and pagination: full-vector atomic guards, coherent primary reads, initial `no-store` and invalidated-snapshot 410 responses remain mandatory.

## Acceptance criteria

1. **AC-WP22-01:** Given invalid identity, origin or target authorization, every mutation is denied with no state change; evidence is a route-by-role negative-test matrix and database comparison.

2. **AC-WP22-02:** Given hostile documents and links, processing stays bounded and cannot execute content or authorize publication; evidence is adversarial input, output and resource-limit receipts.

3. **AC-WP22-03:** Given forbidden destinations or redirected credentials, transport blocks the request without leaking secrets; evidence is controlled-server request logs and sanitized failures.

4. **AC-WP22-04:** Given public HTML, API, crawler and log probes, only approved fields are visible; evidence is field-level leakage assertions and manual review.

5. **AC-WP22-05:** Given correction, expiry and concurrent policy changes, stale public claims and snapshots cease serving; evidence is race traces and recovery/retention receipts.

6. **AC-WP22-06:** Given the findings register, no unresolved release-blocking finding is waived by the implementer alone; evidence is independent disposition, residual risk owner and scoped acceptance.
