## Contract requirements

The new mode must be a strict discriminated alternative to the existing work/institution search scopes. A fixed scope binds the exact bare DOI spelling, canonical DOI identity, selected factual fields and singleton budgets into its immutable scope digest. The exact request is anonymous-provider-compatible `/v1/works` with fixed `filter=doi:<literal>`, fixed factual `select`, and `rows=1`; no dynamic parameter, page parameter, cursor, checkpoint or continuation may enter the request. Source access, enrolled registry authority and permission receipts remain separate.

The endpoint constructor sorts query keys. Prior selected Crossref captures used `filter,select,rows`, while the canonical runtime constructor uses `filter,rows,select`. Exact endpoint validation compares serialized URLs. Preserve every prior acquisition receipt and body unchanged; newly coordinated requests must use the constructed canonical URL verbatim to qualify exact original request compatibility. Reusing old bytes under a different URL is a separately labelled offline payload check, not a rewrite of the actual request.

The response must contain exactly one item, a consistent total of one, and the requested canonical DOI; reject missing, extra, wrong or duplicate results before raw retention. A present `next-cursor`, even null, contradicts this fixed mode. Reject unexpected selected item fields and preserve the whole-payload privacy/material guard. DOI literal spelling in the request and canonical DOI equality in the result are different facts. Reported publication dates retain source precision; observed time is not publication time, and selected bibliographic fields do not establish correction/retraction completeness.

Inspection, retained-page replay and next-page lookup must all enforce the fixed mode's initial-only state, exact configuration/request/source/parser binding, request/body digests and endpoint equality. Repeated polling requires a new reviewed acquisition, not a fabricated continuation. Existing search scope hashes, work/institution API behavior and cursor ancestry checks remain backward-compatible. Local synthetic authority must be explicit in tests and cannot become authenticated provider permission or WP03 human truth.

## Evidence review boundary

Any added native material needs exact source identity, immutable body and observation hashes, complete field/URI inspection, rights scope, request budget and actual outcomes, including rejected or rate-limited attempts. Work-time affiliation, actual local contribution, present professional location, account/person identity, article rights and clinical effectiveness remain separate decisions.
