## Configuration, migration and rollback controls

1. GL11 refreshes actual Worker version, exact source/build identity, custom-domain routing, feature variables, asset bundle, cron and D1 bindings through currently authorized read-only means. Root observed version 105/build c8b36d7 and a ledger through 0040 at baseline; production `LEADERSHIP_MARKUP_CAPTURE_ENABLED=true` is absent from the tracked config and must be preserved or explicitly reconciled. Reconcile the Watch flag contradiction and all current state against prior acceptance. Do not print or copy credentials. A repository value, `schemaVersion: 0045`, prior incident note or healthy endpoint alone does not establish the remote migration ledger.
2. Select the reviewed static snapshot design first. No new remote D1 migration, scheduler, database, service, or paid plan is presumed. If implementation actually requires a migration or new service, define the scoped change, consumers, data preservation, compatible prior Worker, local migration/recovery rehearsal and applicable authority before application. Existing 0041–0045 files are **source present**, not proof of remote application.
3. Capture an exact candidate and previous compatible Worker/snapshot version at release time, including current flags and generated asset hashes. Rehearse disabling discovery and restoring the previous projection in isolation while preserving News/Events/Watch and the latest removal decisions. An old snapshot must not revive a removed claim. The existing OPERATIONS rollback instructions describe a prior bundle and additive historical policy migrations; they do not qualify the new candidate, current production state or current discovery tombstones.
4. On a blocking regression, private-data exposure, false attribution or failed readback, stop the release and use the candidate-specific reviewed correction/rollback path under the user's granted deployment scope. Verify the actual resulting version and behavior. Code rollback is not a D1 restore; any destructive recovery requires its own reviewed scope. Do not change DNS, service schedules or unrelated data to obtain a clean rollback.
