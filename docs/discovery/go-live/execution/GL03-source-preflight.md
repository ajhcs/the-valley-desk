## Transport and whole-body inspection

The manifest's exact URL is the only authorized endpoint for each attempt, no query substitutions, credentials or automatic followups. A transport must enforce a 25-second outer deadline, no redirects or retry, one page, at most five result items (G04 one), `Accept-Encoding: identity`, actual response encoding absent or identity, and at most 48,000 decoded bytes read. Fail closed on missing/invalid status, non-200, unexpected content type (JSON, with optional UTF-8 charset only), invalid UTF-8, compression, oversize, malformed JSON, non-finite/unsafe numbers, duplicate keys, depth/node abuse, unexpected root or more items. Do not rely on `Content-Length` alone. Treat 403/429 or refusal as refused, timeout/network as unknown, redirects as refused/incomplete; record status and no body, do not retry or route around blocks. The source operator must independently prove its egress honors these controls; the existing transport supports manual redirects but may follow them, so it does not by itself establish this stricter zero-redirect policy.

Before any persistent write, inspect the **entire decoded response**, keys and all nested values including discarded values, and headers designated for safe receipt. Apply the existing strict UTF-8/duplicate-key/structural and recursive contact/credential/material checks in `src/ingest/discovery/metadata-preflight.ts` with the appropriate GitHub route discriminator, and validate the stricter approved key census in the manifest. Historical tests and DTOs do not demonstrate this path was used on these responses. Reject any unknown field at any depth; never persist unknown names or contents. For GitHub, census is the union of historical repository keys in manifest, with its explicit owner/license keys; search root is exactly `total_count`, `incomplete_results`, `items`, and `text_matches` is absent or empty. All non-projected metadata (including description, homepage, URL templates, topics, user and license details) is screened then discarded. Only the exact alias-bound GitHub SSH form may pass the existing privacy scanner; it is not retained. Contact-like, secret-like or prohibited material in any field fails the entire attempt, not just the offending field. No raw error body or response headers containing credentials/contact are written to logs.

For C01 the approved shape is root keys `status`, `message-type`, `message-version`, `message`; `status=ok`, `message-type=work-list`; message keys limited to `facets`, `total-results`, `items`, `items-per-page`, `query` and optional `next-cursor`. `facets` must be empty, `query` limited to `start-index` and `search-terms`; the latter must equal the exact manifest query, start-index must be zero, items-per-page must be five and total-results must be at least the returned item count. GitHub search total_count must likewise be at least the returned item count. Items are restricted to selected fields. DOI, type and URL are strings; title is array of strings; published object permits only `date-parts`, an array of one integer array; `author`, `relation`, `license`, and all other unselected fields are rejected if present. All objects/arrays, including any unexpected nested fields, pass recursive privacy and material checks, and any other nested field fails. This deliberately narrow provisional shape may result in a rejected response; do not broaden it after seeing results without a revised independently reviewed preflight. A DOI and title are required for each retained publication lead. C01 permits only native types `journal-article`, `proceedings-article`, `book-chapter`, `dissertation` and `report`; any other type fails the entire probe. This is a method restriction, not a general exclusion of preprints or other works from the service. For a safe HTTPS URL reject userinfo, fragments, contact-like text, tokens and unsafe query values.

`metadata-preflight.ts` rejects restricted keys except null contact slots and rejects nonempty Crossref abstract/full text; it is not a complete field whitelist, source-rights decision, private-data detector, size/HTTP guard, or public admission engine. An operator must add the above field and type gates independently before retaining anything. Do not use the existing collection store path if it persists the native response body. Inspect ephemeral memory only and destroy it after the bounded decision; if full inspection cannot be assured, do not run the probe.

## Compatibility and evidence contract

GitHub adapter routes cover repository, inventory and search, and its parser checks bindings and continuation, but its normal collection/replay expects a retained native representation. No claim is made that the production adapter path or D1 was run. Crossref `qualifyDiscoveryCrossrefScope` requires a date-window and cursor for search and `source()` explicitly rejects `select` in the search template; selected-field C01 is **not compatible with that native adapter search path**. The fixed DOI qualification does not cover C01. A separately reviewed bounded ephemeral inspector/serializer must validate C01; root atomically marks the attempt and supplies its permit in memory, refuses a repeated issued page before HTTP, and writes no persistent permit file; do not quietly remove `select`, treat a fixed-DOI test as evidence, or introduce a source activation. If unavailable, leave C01 pending. PubMed has no independently qualified exact search/field-retention route here and is not substituted.

On passing whole-body and source-specific validation, a **fact packet** contains only the `DirectoryFactPacket` fields: each fact has native ID, kind, title, canonical URL, owner type (GitHub), archived/fork flags, field pointers, and a private pending frontier lead carrying source dates and provenance. For GitHub the title is the source `full_name`; owner ID and login are checked but discarded as standalone values (the login remains part of `full_name`), and public/private and disabled values are checked and discarded. For Crossref the retained facts are DOI, first title, DOI URL and published date in the lead's `sourceDates`. Native type is screened against the allowed set and discarded; it is not represented as a retained native type. No description, free-text match, author, affiliation, relation, license, source text or raw URL template is retained. Field pointers identify the native JSON locations used during ephemeral inspection and the fact packet itself supplies the selected fields. Safe packets are private review leads, not admitted public works.

A separate **receipt** binds manifest ID and hash, exact request ID/URL, observation time, status, validated content type and encoding, byte count, item count, outcome, safe continuation state/metadata, native response SHA-256 calculated in memory, and canonical facts-array SHA-256 (`projectionSha256`), whole canonical fact-packet SHA-256 (`packetSha256`) and packet path. Safe continuation is presence/absence and next-page number where verified against exact origin/route/parameters; never copy arbitrary URL or secrets. A body digest is a commitment to unretained bytes, not a body capture or replayable evidence. The facts-array digest binds the selected fact array; the separate whole-packet digest includes packet metadata and the facts-array digest. Neither is the native response hash; reviewers cannot independently reproduce the native projection from unretained bytes and must treat it as operator-attested. For failure, persist only safe status/outcome/count; the current sender clears all three digests when no packet passes; never body content or offending values. Sol reviews each receipt, packet, actual implementation and limitation; root controls any later batch. The absence of continuation or provider totals is not evidence of exhaustive account coverage if any ambiguity or cap remains.
