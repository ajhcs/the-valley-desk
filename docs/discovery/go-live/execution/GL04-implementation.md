# GL04 implementation notes

The offline directory builder reads `docs/discovery/go-live/evidence/GL04/selection.json` and emits `src/content/discovery-directory-catalog.json`. Run `node --import tsx/esm scripts/build-discovery-directory.mjs` to build or append `--check` to compare. The selected checkout's qualified Node wrapper applies to both. It also emits an allowlisted `src/content/discovery-directory-removals.json` containing only snapshot version and removed IDs, plus private `generation-state.json` and `generation-report.json` under the GL04 evidence directory for a separately reviewed future prior-state pin and change review. Each build also writes an immutable, content-addressed `generations/<sha256>.json` archive of the exact generation-state bytes; an existing archive with different bytes causes a failure. The private report records its `nextPriorState` path and SHA-256. After review, pin that descriptor for a later generation; the builder requires this archive path for prior input, keeps it intact, and checks the new archive on repeat builds. The builder also checks the exact bytes of the separately pinned Sol review artifact before building and fails closed until the reviewed `DIRECTORY_REVIEW_AUTHORITY` exists and pins the canonical entire selection digest and the named operator and reviewer. CLI inputs cannot replace that authority. Canonical JSON sorts object keys recursively, preserves array order and hashes UTF-8 bytes using SHA-256. Each decision receipt binds the work hash with `reviewRefs` omitted; the work's one review reference binds the canonical receipt hash. The detached selection digest also binds the complete work, receipts, evidence, dispositions and bindings.

The retained JSON evidence is hash checked and exact pointers are resolved. Native provider fields have source-specific pointer, identity and date checks. The GL03 adapter checks the retained fact packet and receipt hashes and tuple, plus native pointer descriptors; the original native response was discarded and is not reconstructed. Curated observation bindings retain the distinction between an operator's factual note and the primary source. Binding a reviewed claim to a note does not mechanically prove the claim: the named reviewers must assess the source, scope, identity and permitted use. Selection hashes and named roles are not cryptographic identity authentication: a party able to rewrite the trusted code and review artifacts can alter the authority. The trust boundary is the reviewed PR and operator-controlled code, not a new signing system. No model result grants approval.

The v1 snapshot and read helpers contain only approved works. Holds and source observations stay private. List counts describe works; support objects and verified project groups are not inferred. Cursors bind the complete snapshot digest and query. A reviewed relation observation must name both endpoint identities and its direction; linked works must exist in the same resulting snapshot. A separately anchored prior generation carries forward accepted works and tombstones. A correction targets the exact prior ID and revision, preserves its canonical native identity and increments the revision. A removal targets the exact prior ID and revision, suppresses the work and records its ID and canonical native-identity digest; later admissions cannot reuse either. Holding a proposal leaves the prior work unchanged; a duplicate disposition requires an existing distinct target ID and exact revision. Removing a relation target requires the same transaction to correct dependent relations, or snapshot validation fails. This local transition mechanism does not constitute an operational rollback rehearsal. GL03's incomplete scopes and weak candidates remain preserved in the selection/frontier; no collection, source HTTP request, deployment, scheduler or database operation is performed by this builder.

Focused tests exercise deterministic reproduction, changed-selection and forged-review rejection, evidence corruption, pointer/extra-field checks, author index, correction, hold, removal and resurrection, read pagination and changed-snapshot invalidation. A diagnostic run with a dynamically derived digest is only an engineering test; it grants no approval. Actual independent review, the detached authority pin, generated snapshot, integrated route checks and package acceptance are separate decisions.
