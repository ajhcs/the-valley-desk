# WP07 collector implementation — Terra

The local collector implements a bounded, explicitly invoked step over a frozen round and its current fenced claim. It uses injected server dependencies; it does not register a scheduler, activate providers or use native network access. Root owns package acceptance and final integration qualification.

Each step resolves the next unfinished durable slot, with one page attempt per source per round. New enrollments wait for the next round. A source found revoked before claim is recorded as a skipped slot; a source disabled at issuance produces a durable `failure/disabled` outcome. Neither path makes an unauthorized send. Final blocked, failed and timed-out slots advance under the current fence. This provides conditional opportunity for a finite cohort when dispatch and lease recovery continue; it does not guarantee delivery or complete coverage.

A successful page requires one guarded D1 transaction for the raw representation, private normalized leads, collection receipt, contiguous checkpoint, health success, cursor advance and budget settlement. It is not a `DiscoverySourcePage` and does not create catalog subjects, evidence references or publication authority. Root's [EX10 decision](../implementation-decisions.md#ex10--durable-collection-composition-and-bounded-round-policy) retains the accepted WP06 adapter while adding a trusted provisional parser: the server-owned store validates the received attempt and snapshots bytes and request, then keeps the draft behind a bounded opaque handle. The commit consumes that handle and the ephemeral issuance token. The handle cannot be supplied as caller-authored leads; durable replay is resolved before requiring it.

Stable per-claim operation IDs and durable result lookup resolve a lost acknowledgment without another fetch. A dispatched but unfinished request remains charged and uncertain. A lost uncommitted token or handle does not authorize free replay. Query, window and configuration bindings cannot be spliced into another chain; expired continuations require a new bounded cohort. Empty nonterminal pages, missing terminal pages, loops, rejected rows and truncation do not establish complete inventory coverage. Last attempted, successful, complete and public refresh times remain distinct; failed refresh preserves still-permitted last-good evidence.

Slot claim and takeover are coupled to the source lease; the collector never independently reacquires one after losing the slot. A timed-out database mutation yields uncertain until its durable outcome is reconciled. A late parser result is discarded and cannot start a commit. Timeout finalization is fenced and attempted at most once only when no mutation remains in flight and the original lease is still live. The collector checks elapsed monotonic time as well as wall time, including the resolved source cap and any shorter issued deadline; its egress wrapper checks the outer deadline immediately before send. An already admitted external request remains charged and cannot be atomically retracted with a database change. Asynchronous waits are bounded, but synchronous parser CPU cannot be preempted; the 48,000-byte input bound is not a proof of CPU time.

## Validation and findings

The owner's [focused collector tests](../../../test/discovery-collector.test.ts) passed **6/6** with synthetic store doubles, including uncertain issue/commit outcomes, lost-token no-resend, an overrun beyond the original lease, redacted failures, delayed-credential egress cutoff, source cap and shorter issued deadline under a frozen clock. App TypeScript and standalone strict test typecheck passed; the latter used installed `/usr/share/nodejs/@types` because project-local Node types are absent. The focused log is `.discovery-work/wp07-terra/collector-test-v2.log`, SHA-256 `86d20cdbedae03eb29c64fb0ba49fbfcc81b83297642c25561b9485e0715f0be`. These tests do not establish D1 atomicity.

The separate Sol-authored [actual local D1 suite](wp07-tests-sol.md) passed **33/33**, with 16 recorded inputs unchanged before and after. It tests actual migrations 0001–0044, atomic commit and rollback, crash replay, linked-lease takeover, fair slots, coverage, scope removal and charged uncertainty. Its earlier failures, including health DTO readback and a one-second continuation fixture whose commit exceeded the deadline, remain retained. The valid loop fixture uses a longer lifetime; dedicated expiry tests remain separate.

[Astra's independent review](wp07-astra.md) passed **21/21** against 19 stable inputs. Its challenges produced corrections for prepared-draft forgery, receipt integrity, competing skip/claim state, and the collector's shorter-issued-deadline monotonic calculation. Its actual-D1 frozen-clock check confirms a delayed issue cannot reset that shorter deadline or cause a late send. Astra recommends root acceptance within the local synthetic scope after integration gates.

Frozen owner inputs: collector `abfcf200a6dcbbb0f562efb40ecf6b05a529091f2bf590b5c69c5202f448bb6f`; focused test `17aa23678b3965c215cd30753e9429950e8e938f9b996de2dfcea3361577591d`. The full suite and independent review have their own exact input manifests and receipts. Root's integration qualification was still running when this handoff was written.

These checks do not establish live provider access, real credential or reviewer identity, source truth, complete upstream inventory, production scheduling, public catalog materialization, physical backup erasure or deployment readiness. Restore reconciliation, WP14 materialization and the qualified connect-time egress boundary remain separate work.
