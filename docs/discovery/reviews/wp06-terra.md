# WP06 endpoint and transport implementation — Terra

Status: implementation under independent review; no package acceptance. Owned files: `src/ingest/discovery/endpoint.ts` and `src/ingest/discovery/transport.ts`. Registry, adapter, migration and independent local-D1 tests are separate owners' work.

The constructor accepts reviewed literal HTTPS origin/path and bounded typed parameter entries, rejects duplicates/unknown names and noncanonical URL spellings, and checks a supplied continuation token digest and expiry. The registry remains responsible for authenticating continuation and its committed parent receipt. Literal IPs and local hostname forms are rejected early; syntactic hostname checks cannot establish public DNS or connection safety.

The transport resolves a registry-issued plan ID, requires injected connect-time public-destination egress, resolves header-only credentials bound to the exact origin and checks expiry again after reservation. Each attempt uses a durable nonreusable reservation before send. The current exact-issued-endpoint policy rejects a redirect to a changed URL, including a same-origin URL, before another send; cross-origin redirects are denied without forwarding headers. A changed URL requires a new issuance. Response reads have a shared wall/monotonic deadline, copy each chunk, enforce the retained-byte ceiling, and cancel on failure. Final successful response hashes bind the registry receipt to acquired bytes. Long `Retry-After` values do not become immediate retries. External resolver and egress errors are translated to static codes.

The transport yields provisional bytes and a registry plan, never a durable page or checkpoint acknowledgment. Synthetic injected egress cannot qualify production DNS, actual credential ownership or provider access. The WP07 retention/page/checkpoint transaction and connection-time egress qualification remain separate obligations. An admission committed before a concurrent revocation may still dispatch; the database and network are not one transaction.

An isolated synthetic endpoint smoke checked encoded query construction, exact round trip, duplicate/unknown parameters and IP-literal denial. The app TypeScript check passed during development. Full local-D1 acceptance and adversarial tests are pending from the independent test owner; this note is not an integration receipt.

Follow-up local checks: five direct synthetic transport probes exercised redaction of credential resolver exceptions, throwing credential getters, egress exceptions and body-read exceptions, plus a reused byte buffer across delivered reads. All passed after setting the fixture stream's high-water mark to zero. An initial auto-prefetch fixture mutated queued memory before its first read was delivered, which a consumer cannot reconstruct; that failed attempt remains part of the task record. These probes use a stub registry, not D1 transaction evidence. The app typecheck passed after the changes.

Root found a URL normalization defect: `URLSearchParams` replaces unpaired UTF-16 surrogates, so a token or query could be sent with different characters from its issued binding. The constructor now rejects unpaired high and low surrogates in fixed, enum and dynamic values before encoding; an explicit synthetic probe accepts a valid emoji pair. Root's pre-fix counterexample is retained at `.discovery-work/wp06/root/endpoint-unicode-before.log`.

Deadline qualification: plan lookup starts with a fixed 300-second hard ceiling because the source-specific budget is not yet known. When lookup returns, elapsed monotonic time is immediately compared with the resolved source wall-time cap and absolute deadline; if already exceeded, no reservation or network send starts. This cannot retroactively cancel a lookup at a shorter, previously unknown source cap. Later awaits and body reads share the remaining budget.
