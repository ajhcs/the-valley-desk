# Local native and SDK journey repair

The released Worker uses verified signed Access application JWTs. The local private-Ops journey now uses ephemeral RS256 signing keys and a synthetic issuer/audience through that same guard; it no longer supplies the obsolete context-only identity. Signing material remains in memory. The JWKS response is mocked, and Node fetch allows only that fixture URL or the ephemeral loopback server. Browser HTTP traffic is blocked outside the local adapter. The exact Vite development WebSocket handshake is mocked in memory; other sockets close without connecting. These checks are synthetic, not a real owner login.

React development remounting can briefly register three tools, dispose them, and register them again. The previous count-only check could pass before disposal, then execute with an absent RegisteredTool. Readiness now requires each of the three exact names across render frames; execution reacquires a current handle and polls discovery for at most 10 seconds if a remount intervenes. Tool execution is attempted once and any failure remains a failure. There is no fixed startup sleep or execution retry. Server HMR is disabled; its development client receives a bounded synthetic connected handshake without a real socket connection. This avoids live-domain WebSocket traffic and does not mock tool execution.

The private flow checks anonymous denial, no public-page tools, all three read tools, invalid-query denial, nonblank Ops page identity, SPA disposal/re-entry, authenticated shell reload, and denial after removing the synthetic session. Response status is attributed to its own request, including concurrent metadata requests. Expected 404 console messages and deliberately blocked resource failures are retained with origin/path evidence. A blocked-resource error is accepted only when its exact origin/path matches the HTTP policy denial; unexpected console errors or page exceptions fail the journey. The SDK/local-preview flow retains its provenance, disambiguation, safe-error and decoded-pixel comparisons in light/dark desktop/mobile modes.

Run only on BuilderBob using its existing Node, Playwright, Chromium and libraries. Existing dependencies and protocol compatibility remain unchanged. The standard journey arguments are evidence directory, retained source captures, retained PubMed projection, with `--private-ops` selecting the private flow (the two retained-input arguments are unused in that mode).

A live owner session remains unverified. The supported human action is to open https://thevalleydesk.org/ops in a regular browser and complete the existing Access sign-in as clyons@ajhcs.org. Do not copy cookies, tokens, OTPs or credentials into this harness. No production code, source activation, cron, credential, deployment or persistent service change is included.
