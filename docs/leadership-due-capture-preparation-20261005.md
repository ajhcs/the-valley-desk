## Implemented local preparation

- An optional capture hook reuses the normal bounded Fetch response reader. Existing source eligibility, retry holds, request headers, redirect allowlist, alternate selection, collection caps, parser contracts, role verification, schedules and alerts are unchanged.
- Exact response-body bytes are hashed separately from decoded UTF-8 text and retained as base64, with source ID, snapshot ID, configured/attempted/validated final URLs, scheduler timestamp, actual receipt timestamp, HTTP status/content type, byte count and decoding semantics. These are Fetch body bytes, after any transport decompression, not compressed wire bytes. Existing snapshot content hashes/byte counts retain their existing semantics.
- Capture needs the exact flag value `LEADERSHIP_MARKUP_CAPTURE_ENABLED=true`, both scheduler and wall-clock within `[2026-10-05T02:30:26.038Z, 2026-10-05T06:00:00.000Z)`, a fixed allowed source/primary URL and an explicit HTML content type. The flag is absent from `wrangler.jsonc`. No production setting was changed.
- Only the response belonging to the monitor's selected snapshot can be retained. No additional request is made. Blocked responses, off-host redirects, missing/other content types, over-limit responses and suffix-only scans provide no full-markup capture. A response completing at or after the deadline is discarded. Persistence checks wall-clock again before submission, and a migration trigger rejects an insert that executes outside the same window, including a response received earlier. An unavailable capture table skips capture without changing collection. Optional persistence failures produce counts only, never raw markup in logs.
- Proposed additive migration `0040_leadership_markup_captures.sql` creates one separate bounded table in the existing D1 database. Exactly seven source IDs are allowed, with a primary key and `ON CONFLICT DO NOTHING`: collection never overwrites a first capture. Maximum raw body is 512,000 bytes / 682,668 base64 characters. The table also records DB insertion time and fixes row expiry to Oct 6 06:00 UTC. The existing scheduled leadership stage deletes expired capture rows independently of flag enablement; before expiry it makes no retention query. No source, role, registry or schedule rows are backfilled or altered. The schema stamp advances to 0040 only in this local candidate.
- Disconnected preparation contracts for the exact seven sources have `qualified=false`, `rawCaptureSha256=null`, and `officialSelectors=null`. The offline DOM harness uses explicitly invented `data-fixture-*` selectors. Synthetic previews always remain partial, unverified, and unable to renew freshness or authorize departures. They do not assign registry person IDs. Article claims preserve an available source publication date; an undated claim stays undated. No synthetic fixture is represented as captured institutional markup.
